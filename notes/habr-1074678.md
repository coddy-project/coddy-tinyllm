# Тернарная нейронка на C# - notes

Source: <https://habr.com/ru/articles/1074678/>
Code: <https://github.com/virex-84/LLamaTritLLM> (MIT, .NET 8, one commit, 2026-09-11)
Release with weights: <https://github.com/virex-84/LLamaTritLLM/releases/tag/v1.0>

## What it argues

The interesting half of the article is the argument for why *ternary* rather than binary. A neuron
has three useful behaviours - amplify, attenuate, stay silent - and a single bit can only encode two
of them. A `[-1,+1]` binary weight can never go quiet, so weak and irrelevant features keep
contributing noise and the network cannot become selective; a `[0,+1]` one can only amplify, which
rules out non-monotonic functions. A trit, at 1.585 bits, is the smallest complete neuron. The
zeros are not waste - they are the sparsity that suppresses noise and skips computation.

The rest is standard BitNet b1.58: train with BF16 master weights, quantise to trits on every
forward pass with a per-layer threshold equal to the mean absolute weight of that layer, push the
gradient back through the quantiser unchanged (straight-through estimator) so the master weights
drift continuously while the trits switch discretely. At inference the master weights are discarded
and matrix multiplication collapses into additions. The embedding and the output head stay
non-ternary.

Nice historical aside: Сетунь (1958, Брусенцов), a working ternary computer with a symmetric
`[-1,0,1]` code and 6-trit trytes.

## What the code is

Two .NET projects, ~6.3k lines. `TernaryTraining` carries a hand-written autograd, AdamW, a BPE
tokenizer and QAT with an STE over FP32 latent weights; `TernaryInference` loads the packed file and
chats. The packing is the part worth reading: multi-plane ternary, `w ≈ Σ_p scale[p]·t[p]`, five
trits per byte in base 3, FP16 per-group scales. `planes=1` is 1.58 bit; more planes trade size for
capacity, which is a neat way to make the format tunable.

## Scale, stated plainly

The shipped configurations are **106 496** and **49 152 parameters** - embedding 64 or 32, one layer,
one head, vocab 16 000 - producing model files of 28.9 KB and 17.1 KB. The training corpus is
`data/pretraining_data.json`: 22 Russian sentences, 4 KB. The inference kernel is a scalar
per-output-row dot product; there is no SIMD, no int8 path, no parallelism anywhere in the tree. The
README says it is an educational artefact, and it is right.

## What it is worth to this project

A readable, single-language reference for trit packing and STE-based QAT, and a reminder that the
BitNet recipe is small enough for one person to implement. That is all. It is not a base to build
on, not a performance reference, and not a source of a usable model - the serious ternary work is
[microsoft/BitNet](https://github.com/microsoft/BitNet) for inference kernels and
[BitNet Distillation](https://arxiv.org/abs/2510.13998) for getting a ternary model that is actually
good, both covered in [docs/02-prior-art.md](../docs/02-prior-art.md).
